# ShareVibeX 0.4.1 — FFmpeg capability parsing correction

This patch corrects a false "Missing: pad filter, format filter" result. Newer FFmpeg builds list two capability flags before a filter name; older builds list three. ShareVibeX previously required three and also accepted legend rows as filters. Both formats are now supported, with real input/output signatures required.

Source reference: https://github.com/FFmpeg/FFmpeg/blob/master/fftools/opt_common.c (show_filters).

The new recording/pause/in-place playback/A–B editing workflow requested on 2026-11-03 is a separate pending design, not implemented by this patch. Recording controls and destination selection remain those of 0.4.0.

## User checks

1. Exit the earlier instance through its tray menu. Extract the whole 0.4.1 ZIP into a writable folder. To retain preferences, copy your previous data/settings.json before starting.
2. Settings > Video > Test FFmpeg using the same system executable from the report. Available pad/format/scale filters should no longer be reported missing merely because of two-flag rows.
3. A genuinely missing selected filter, encoder or input must still be reported. Changing the parser does not install missing FFmpeg components or validate GPU initialization.
4. Try a short silent recording with MP4/libx264, then playback/microphone recording. Confirm clean Stop, playable output and audio. If startup still fails, retain the exact new error; a filter-list correction cannot establish that every runtime dependency works.
5. Follow the full 0.4.0 checklist in docs/testing/2026-11-03-manual-0.4.0.md for native recording/device acceptance.

The agent tests parsing with synthetic stdout/stderr fixtures and runs internal regression tests. It does not launch the app, query the actual system FFmpeg, open audio devices or record the desktop. Native acceptance remains assigned to the user.

# ShareVibeX 0.5.0 — user acceptance checklist

The agent ran internal/headless fixtures only. It did not launch ShareVibeX, actual FFmpeg, native screen capture, audio devices, playback hardware or the live clipboard. The cases below are pending real Windows acceptance; compilation/tests are not proof of A/V quality, capture exclusion or receiving-app behavior.

## Start and regression

1. Exit the older copy using its tray menu. Extract the whole ZIP to a writable folder. Optionally copy the previous data/settings.json before launch. Start ShareVibeX.App.exe: only the tray icon should appear. Resolve any capture-shortcut conflict in Settings.
2. Verify System and Contrast themes, custom Settings title bar, compact Video tabs and image quality/format. A missing FFmpeg must not prevent screenshots or saving other settings. Test FFmpeg should accept the reported newer two-flag filter listing.
3. Invoke capture over changing content: selection stays live and undimmed; dragging shows resolution only. The released region has screenshot/video/cancel icons. Enter/Ctrl+C immediately copies a fresh crop. Explicit screenshot editing freezes pixels, preserves annotation tools/palette/text/Ctrl-drag/wheel, and excludes UI from Copy/Save. Check image copy in Win+V and a receiving app.

## Record and audio

4. Choose Video: Record / Sound / Microphone / Back icons and short tooltips. Record starts immediately without a destination picker. Test a short silent MP4/libx264 clip first, then system-only, microphone-only and mixed clips. Verify selected devices, channel format and actual content; both sources off should yield no final audio track. Native mic mixing with DirectShow must report its limitation rather than silently ignore it.
5. Confirm duration, resolution, measured average bitrate and bytes. Controls should show Stop / Pause / Microphone / Cancel. Inspect the output: no overlay, border, tooltip or runtime panel may be captured. Test near monitor edges, negative coordinates, 125/150/200% DPI and a full-monitor region. If exclusion and outside placement are both unavailable, startup should refuse clearly.
6. Pause several times, leave a long wall-clock pause, toggle mic while paused and recording, resume, then Stop. Paused time must be absent, audio transitions must match the icons, and device access must stop when disabled/paused. Stop while paused must not add empty media. Test configured duration limits across segments. Custom command Pause must report its documented restriction.
7. Try Stop via panel, hotkey and tray. Cancel must discard only its managed session after child processes/devices release. Try device removal, missing configured endpoints, unsupported surround, GPU encoder failure and display layout change; errors must retain recoverable media and never silently switch source/encoder. Check long-run A/V sync separately.

## In-place playback and A–B

8. Stop should show the first frame paused inside the selected physical region, with letterboxing as needed. The rest of the desktop stays interactive. Play/Pause, audible playback, seek near start/end and rapid repeated seek should stay coherent. Preview is capped at 960×540/30fps; saved video keeps its output dimensions.
9. Set A/B from the playhead; drag the two handles. Check arrow-key adjustment (A) and Shift+arrow (B). Keep a middle interval, then Remove part of that edited timeline; verify video frames, audio and new duration. Reset must restore the stopped original. Empty A–B and Remove-all must be rejected without losing the current preview.
10. Cancel during a longer re-encode and during edited-thumbnail loading: the preceding paused revision must remain usable. Try another edit/Play/Save afterward. A decoder/encoder failure must show an error with retained source, without releasing session ownership while work still runs.

## File copy, Save and Close

11. Copy an edited video into Telegram and another file-capable receiver; verify current content/duration/audio. Repeated Copy without editing should reference the same immutable cache file. Edit and Copy again; the previous copied file must remain unchanged. Close preview and exit ShareVibeX, then paste again: the file should still exist. Receiver behavior determines file/video/animation presentation; GIF conversion is not promised.
12. Save MP4, then MKV to a chosen folder. Cancel the picker: keep preview and unsaved state. Test overwrite success; test failed/canceled rendering to an existing destination: old bytes must survive. A busy action must prevent concurrent edits/seek/export. Cancel should release the child job and allow retry.
13. Close an unexported preview: Continue keeps it; Save with picker cancellation keeps it; Save success closes it; Discard removes its recognized temporary session files. Copy/Save without Close keeps viewing available. Successful export then Close must keep saved/cache files and release the capture shortcut for another session. Test Exit -> Stop and review -> Save/Discard/Continue, including Continue canceling app exit.
14. If a session file is locked and cleanup fails, retain it, report the problem and allow Close retry after releasing the lock. Verify child FFmpeg processes and audio devices do not remain after successful Close/Cancel/Exit.

## Recovery and portability

15. Retain a finalized session by interrupting the app, then restart and use tray Retained recordings. It should reopen supported finalized metadata/edits. Interrupted segments and legacy metadata are manual-recovery only through Open folder; no repaired-media claim. Corrupt manifests must not open arbitrary files or authorize deletion. Discard requires a second click and preserves unknown files.
16. Copy cache never expires automatically. Clear copied videos requires a second confirmation and removes only recognized cache files; existing clipboard/history references to removed files will stop working. Saved destinations and unknown cache files must survive. Do not clear data you still need to paste.
17. Start another recording after preview/recovery closure. Move a clean portable folder and verify settings/FFmpeg discovery again. Do not move a folder with active work or needed clipboard references: file paths are absolute. No service, startup entry or system PATH change should be installed.

If a case fails, retain the exact action sequence, settings/FFmpeg version, monitor layout/DPI, error, and relevant retained session/diagnostic log. Logs are opt-in via --diagnostics and may contain paths. Never describe native checks as passed merely because internal tests pass.

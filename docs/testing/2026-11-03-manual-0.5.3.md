# ShareVibeX 0.5.3 — startup cancellation and interface checks

No native app, capture, FFmpeg, devices or clipboard were launched by the agent. Internal/headless startup fixtures cover Stop/Cancel before session creation, during countdown and while waiting for first frame; actual Windows acceptance remains with the user.

- Video editor: A/B time labels and Reset edits button are removed; current-frame time remains.
- General > Recording countdown: 0–10 seconds, default 0. Nonzero countdown is owned by the active Starting session, so tray Stop/hotkey/Cancel/Exit can cancel it. Check settings persistence, repeated starts and both cancellation buttons at each startup stage.
- A pending first-frame startup is terminated on cancellation/timeout rather than spending the normal graceful recording-finalization timeout waiting for FFmpeg to accept q. Completed recordings still use graceful Stop.
- The capture boundary uses the same cyan dashed styling during live selection, screenshot editing and recording, without a full-region overlay while recording. It remains during startup/countdown/recording/pause/finalization and disappears when entering video editing. Inspect output to confirm borders remain excluded. At unsupported exclusion/desktop boundaries an unsafe strip is omitted rather than recorded.

Instant first-frame startup is not guaranteed. The current pipeline resolves/tests external FFmpeg, initializes selected devices/encoder, then waits for first-frame progress. Tool discovery/capability checks could be prepared earlier, but opening devices or a recorder before explicit Record would start acquisition early. This release offers configurable countdown and cancellation fixes rather than claiming zero latency or silently capturing before Record. Countdown precedes initialization and is a user-visible delay, not a guarantee of first-frame timing.

Test silent/system/microphone capture with 0 and 3 seconds. Stop/Cancel immediately on opening controls, during countdown, capability queries, audio initialization and first-frame wait. Confirm no stuck panel/child/audio resource, then record again. Retain exact error/log and phase if a native hang remains. The earlier 0.5.2 checklist still applies to export/trash/clipboard behavior.

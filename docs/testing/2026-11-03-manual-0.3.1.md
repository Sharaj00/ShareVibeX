# ShareVibeX 0.3.1 — user verification

The agent ran internal/headless tests with synthetic images, fake capture and fake clipboard only. No real application window, native capture/compositor harness, live clipboard, audio device or real FFmpeg was tested. The user owns these desktop checks.

## Compact Video settings

1. Exit the old copy through the tray and start the extracted 0.3.1 build. Open Settings > Video.
2. Encoding should have video controls on the left and audio controls on the right, like the supplied ShareX reference. FFmpeg path/Browse/Test stays above; additional arguments and custom-command switch stay below.
3. Check at the normal window size and minimum width, including your Windows display scaling. Container and output folder must remain visible and usable, with no overlap/clipping. The page may scroll on a short display, but must not be a long stack of large parameter cards.
4. Scaling and time limit are under Scaling. Effective command/audio preview and estimated size are under Preview. Custom command appears only when enabled; detailed template help expands on demand.
5. Change encoder, fps, scaling and audio options across tabs, Save and reopen. Confirm all values persist and General/Image options are unchanged. Reset affects only Video draft; closing without Save discards changes.
6. Repeat your FFmpeg path/Test checks if desired. Capability testing still does not start recording.

## Live selection

1. Display a moving clock, video or animation, then invoke capture. It should keep updating beneath the selection layer. The whole screen must not become a frozen or darkened image.
2. Drag, move and resize the region. Only the region outline, handles, small instructions and mode toolbar should cover the desktop; no full-screen dimming.
3. Wait for visible content to change, then press Enter. The clipboard must contain the current selected pixels, without editing, toolbar, handles or border. The capture layer closes and tray stays running.
4. Repeat with Ctrl+C. Pressing either shortcut before choosing a mode must use quick capture, even if a mode button has keyboard focus.
5. Cancel with Escape/right-click. There should be no screenshot or clipboard change. Empty selection should not become an implicit full-screen capture.

## Explicit screenshot editing

1. Select a moving region, wait, then click Edit screenshot. The frame should freeze at that action, rather than at initial capture invocation. The existing annotation tools and outside-region dimming appear only now.
2. Add annotations, Copy/Save and compare the result with the frozen editor. It must not acquire a later moving frame during export.
3. Check shape/text/palette/wheel/Ctrl-drag/undo behavior as before. Cancelling Save stays in that same frozen editor.
4. Confirm no selection/editor panels appear in the image. Verify fresh full-color Win+V history and external paste if needed.

## Video selection and limits

Choosing Video must keep the region live. Back returns to mode selection without freezing or changing the region. Record with audio / Record silently remain disabled and the toolbar explains that recording runtime is not implemented in this build. Actual live recording is the next tranche, not a feature claimed here.

## Multiple monitors and failures

Check negative desktop coordinates, mixed scaling and a region crossing monitors if available. Cancelling or changing display layout during a pending screenshot must never reopen closed overlays. A capture failure should show an error and allow retry/cancel. Native transparency/hit-testing and compositor timing remain manual acceptance items, regardless of headless test results.

# ShareVibeX 0.4.0 — recording acceptance checklist

The recording path is implemented and connected in this build. The agent did not run the actual application, native desktop capture/compositor harness, clipboard, FFmpeg or audio devices. Internal tests use synthetic frames/audio, fake recording processes/files and hidden console-only protocol/job tests. Real Windows acceptance below is assigned to the user; these scenarios have not been marked passed by the agent.

## Setup and screenshot correction

1. Exit the older instance. Extract the whole ZIP to a writable folder and run ShareVibeX.App.exe. Settings remain in data/settings.json. Copy your existing settings file before launch if desired.
2. Capture/edit a right-side region similar to the reported528×599 example. The editor should follow the selected region instead of jumping to the opposite edge. Check narrow/wide regions, near-bottom placement, negative coordinates and100/150/200% scaling if available.
3. Copy and Save are monochrome vector icons with tooltips and accessible names. Verify Ctrl+C/Enter/Copy icon and Ctrl+S/Save icon retain their actions. Quick Enter/Ctrl+C before editor entry still copies a fresh unedited image.

## FFmpeg and audio configuration

1. Open Settings > Video. Leave path automatic or choose your FFmpeg executable, then Test FFmpeg. No binary/virtual audio driver is installed by ShareVibeX. Screenshot mode must continue working without FFmpeg.
2. Choose MP4/libx264/AAC first,30fps, original scaling. Hardware encoders require an actual working driver/device; if initialization fails, select H.264/x264 as the software fallback. No silent codec substitution occurs.
3. Devices > Refresh audio devices lists active endpoints only on that action. Choose Windows default or explicit playback/microphone endpoints. Encoding > Audio source selects System playback, Microphone, System+mic or an existing DirectShow device by exact name.
4. Native endpoints currently support mono/stereo PCM16/24/32 or float32. For a surround endpoint, choose/configure a stereo endpoint; unsupported format must produce an explicit error rather than missing dialogue. Opus uses MKV and48000Hz output here.

## Silent recording

1. Invoke capture, select a live region, choose Video, then Record silently. Choose an MP4 destination. Selection and app panels disappear before recording starts; no screenshot frame is frozen for video.
2. Move windows/play animation inside the region. Hover the tray icon for elapsed time. Stop with the capture hotkey (default Ctrl+PrintScreen), tray Stop recording, or a primary tray click.
3. Wait for finalization. Open the saved file: correct region, live motion, chosen cursor setting, expected dimensions, no audio track, panels or selection border. A silent MP4 is GIF-style video for Telegram; this is not a GIF file.
4. Repeat with an odd-sized region and50%/divide-by1.5/target scaling. Content must be padded when needed rather than cropped to even encoder dimensions.

## Audio recording

1. Repeat with Record with audio and System playback. Play recognizable sound and include several seconds of complete silence. Silent gaps must not hang recording or speed up the audio track.
2. Repeat with Microphone, then System+mic. Verify the selected devices, audible channels, source mix and cancellation/error behavior. Confirm the silent button never opens an audio device even when configured devices are unavailable.
3. Make a longer recording and check A/V synchronization at start and end. Real clock drift, native latency and device-specific compatibility are unverified by synthetic tests.
4. If using DirectShow, test your exact installed device; missing dshow input support or an empty name must fail before capture starts. No driver is installed automatically.

## Stop, duration, exit and failures

1. Stop repeatedly/rapidly through hotkey and tray: one final file, no hang or duplicate finalization. Test a positive duration and both normal/custom templates. No time limit must be silently ignored.
2. During recording choose Exit. When a capture-excluded confirmation window is available, Continue recording must leave capture running and Stop and save must finalize before exit. If exclusion cannot be configured, no dialog is shown; stop from the tray before exiting. Verify that any confirmation window is absent from the video on your system.
3. Settings stay unavailable while recording so the app does not place its settings window over recorded content. Previously hidden settings should restore after recording ends, without reopening a window you closed.
4. Try a missing FFmpeg, unavailable GPU encoder, invalid device or unplugged microphone. An error must restore live selection for retry or finish the recording with an explicit failure. It must never report an audio failure as a successful silent video.
5. For a failed/interrupted encoding, an existing final file must remain intact. A nonempty partial is kept beside the destination and its path is reported. A partial may require repair or be unusable after a forced stop; it is not claimed as a finished video.
6. In a disposable test only, terminate ShareVibeX during recording and confirm its FFmpeg child also ends. Windows job lifetime is tested with a synthetic console child, but the real-recording scenario still needs user verification. Recoverable output stays at the partial path.
7. Verify that capture/recording cancellation, repeated sessions and normal completion keep the tray/hotkey usable. Keep earlier screenshot/color/palette/text/settings checks as regressions.

HDR/SDR color, mixed-DPI cross-monitor recording, GPU initialization, device removal, fullscreen behavior and long-run performance remain real-device acceptance checks. The Windows GDI backend is not a Linux runtime implementation.

# ShareVibeX 0.2.3 — user verification

All real desktop and clipboard checks are assigned to the user. The agent did not launch the application, run the native smoke harness, or access the live clipboard.

## Start the new build

1. Exit the previous instance through its tray menu. Extract the entire new ZIP into its own writable directory and start `ShareVibeX.App.exe`.
2. Existing black Windows clipboard history items will stay black. Test a newly copied screenshot from this build; there is no need to clear other clipboard entries.

## Clipboard color regression

1. Capture a region containing a dark interface, bright text, saturated red/green/blue areas, and some white content. Add a colored annotation and use Copy.
2. Open Win+V. The new thumbnail should show the full-color capture rather than a black or monochrome image.
3. Paste directly into a chat. Compare text, annotations, colors, dimensions and orientation with the selected region.
4. Paste into Paint and save as PNG. Reopen the PNG and compare it with the direct paste. It should show the same full-color image.
5. If the application used to produce the reported black PNG has a separate save-from-clipboard operation, repeat that exact operation. It must agree with direct paste and normal screenshot Save.
6. Select the new item from Win+V and repeat the paste/save checks. Earlier black entries are not part of this check.
7. Exit ShareVibeX through its tray menu and paste again. The last copied capture must remain available with correct colors after exit.
8. Repeat with a narrow region of odd pixel width and a capture on a secondary monitor, if available. Verify row alignment, orientation, dimensions and crop.

## Existing behavior

Capture and Copy again, then Capture and Save. The tray must remain running and the hotkey must remain usable after either operation. Settings, editor controls and cancellation behavior should match 0.2.2; the previous checklist is retained in the source archive.

## Internal evidence and limits

Tests use synthetic frames only. They decode the generated DIB independently through Skia's BMP decoder, covering odd-width row alignment, source stride, row order and color channels. An edited crop is saved through the normal PNG save service and compared with clipboard PNG bytes and decoded DIB pixels. These tests do not exercise the Windows clipboard/history service or third-party paste/save applications.

# ShareVibeX 0.5.1 — recording interface refinement

The user confirmed 0.5.0 works. These interface changes have internal/headless checks, but the agent did not launch actual ShareVibeX/FFmpeg/capture/audio/clipboard. Native acceptance of the new presentation remains with the user.

1. Exit the previous copy through its tray menu and extract this entire ZIP to a writable folder. Copy data/settings.json before starting if retaining preferences. Prior source/releases are preserved.
2. Select Video and note the four ready icons' location. Click Record: Stop/Pause/Microphone/Cancel must replace them at the same anchor, using the same 40px slots, spacing and transparent surface. No new large opaque panel or heading should appear. Repeat with the region near each edge and at negative coordinates/125–200% DPI. Native capture safety may use a safe alternative anchor if exclusion is unavailable.
3. Check the dashed capture outline during recording and Pause. It should be confined to thin strips, not freeze/dim/intercept the region interior, and disappear after Stop/Cancel/startup failure. Inspect recorded frames to ensure the outline, panels and tooltips are excluded. When exclusion fails, any drawn strip must remain outside the capture; at desktop edges an unsafe strip is omitted.
4. Record enough time to observe size/bitrate updates. Measured progress or the growing temporary file wins when usable. While the file exposes only its header, estimates show ≈ and a tooltip explains them. Compare original versus scaled resolution, bitrate mode and quality mode, audio on/off. CRF estimates depend strongly on content and are not guaranteed output sizes. Finalized file length must be actual; pauses must not accumulate estimated size/time.
5. Stop into preview: adjacent controls should match the other transparent icon panels. There should be no separate external progress slider or A/B row. Hover inside the recorded video to reveal a single seek track with A/B handles, playhead, current/total time and A/B values. Leaving should hide it even after a mouse click; active dragging should remain visible until release. Tab provides keyboard access.
6. Drag an upper A/B handle: change its bound without seeking. Drag/click the lower track: seek without changing A/B. Set A/B buttons still use the playhead. Keep/Remove/Reset should preserve earlier 0.5.0 behavior. Exercise hide/show and dragging off the video while playing, paused and busy exporting.
7. Previous frame / Next frame must pause playback and step on the original output frame grid, including 60fps recordings despite the 30fps preview cap. Clamp at first/last frame. Check decoded image changes as well as position; synthetic tests cannot establish native FFmpeg seek accuracy.
8. Repeat edits, Copy, Save and unsaved Close Save/Discard/Continue, Cancel during edited-thumbnail loading and another capture afterward. The full 0.5.0 checklist in docs/testing/2026-11-03-manual-0.5.0.md still applies.

## Moving the region during recording

This patch assesses feasibility only; no Ctrl-drag capture handle is exposed. The current FFmpeg gdigrab input initializes clip_rect from offsets during read_header and reads pixels from that fixed rectangle. Moving a drawn border alone would be misleading. Moving on release through an internal segment restart could introduce a gap; smooth live movement would require broader capture plus dynamic cropping or a different capture adapter and separate A/V/performance validation. Region size/scaling/output dimensions should remain fixed if implemented later.

Primary source: https://github.com/FFmpeg/FFmpeg/blob/master/libavdevice/gdigrab.c (gdigrab_read_header and gdigrab_read_packet).

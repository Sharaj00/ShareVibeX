# ShareVibeX 0.2.2 — user verification

The user owns all real desktop checks. The agent did not launch the application, use desktop automation, run the native capture harness, change Windows settings or read/write the live clipboard for this update. Internal/headless tests: 84 passed (37 core, 47 app); Release build: zero warnings/errors.

## Settings and appearance

1. Exit the old copy through its tray menu, then launch this package. Confirm tray-only startup.
2. Open Settings. There should be one custom header with minimize, maximize/restore and close buttons, with no native Windows title bar or application icon strip above it.
3. Drag the header; double-click it to maximize/restore. Check all resize edges/corners. Check closing through its own button while settings are being saved waits for the save; tray Exit should still work.
4. System dark should use dark gray window surfaces and lighter gray cards/controls, with a subtle sidebar selection and Windows accent marker. It should not look like AMOLED. System light follows Windows mode. Contrast keeps black window/card surfaces.

## Palette and wheel

1. Capture an area and click the color swatch: it should open a spectrum/palette with RGB/HSV/hex choices rather than a seven-color name list. Select an arbitrary color and draw a shape.
2. The toolbar must not contain Select/Move, Delete, undo/redo, preset text, or font-size spinner controls.
3. Scroll over the width number. Check it changes by wheel ticks; keyboard Up/Down works when it is focused. For a line/pen/shape, hold the left button and scroll before releasing: the active draft and finished annotation should use the new width.
4. Choose Blur and repeat while drawing its rectangle or ellipse. The wheel should change blur strength before release.

## Move and history

1. Choose Arrow, then hold Ctrl and drag an existing annotation. It should move without creating an arrow or permanently changing tools. A subsequent drag without Ctrl should draw an arrow.
2. Clicking with Ctrl without moving should not add a no-op undo step. Delete removes the selected annotation.
3. Ctrl+Z undoes; Ctrl+Shift+Z redoes. There are no toolbar buttons for these actions. Inside a text field, ordinary text-editing shortcuts remain local to that field.

## Text

1. Choose Text and draw a box. It starts empty, with direct text input on the screenshot. Enter inserts a newline. Resize the bottom-right grip: the text should scale with the box, without a numeric font-size field.
2. Ctrl-drag the active text box to move it. Ctrl+Enter or clicking outside commits. Escape cancels the current text edit first; the next Escape cancels capture.
3. Click committed text with the Text tool to reopen it. Copy or Save while a text edit is active must include the entered text, not omit it or paint the previous version behind it.
4. Compare preview and exported text at normal Windows scaling, especially 150% and 200%. Try Cyrillic and your usual other languages/emoji; rendering uses Avalonia shaping and font fallback rather than raw single-font glyph drawing.
5. Optionally check text spanning a monitor seam. Reopening/committing must preserve its full position and size. The live input is hosted by the clicked monitor and can be visually clipped at a seam; full live multi-monitor continuation remains a limitation. Export preserves the full text rectangle.

## Regression checks

Save PNG/JPEG/WebP and copy/paste as before. Confirm capture/Save/Copy closes only the overlay and the tray remains usable for another capture. Cancelling Save keeps the editor. Check that the toolbar, text edit frame, handles, palette and dimming are excluded from saved images.

## Internal review evidence and limits

Review found north-edge resize event routing, text padding at scaled DPI, seam text clamping and single-font export/fallback problems. Source fixes use tunnel resize handling, shared physical text insets, virtual-desktop text bounds and shared Avalonia text layout. Regression checks cover physical insets at 150/200%, seam bounds preservation, fitted font growth, focused Ctrl+Enter, clipping/color of shaped exported text, and existing capture/settings/clipboard/format behavior using synthetic fixtures.

Real native snap behavior, physical cross-monitor input, popup focus, palette/color agreement with the supplied screenshots, actual clipboard/save dialogs and large-desktop rendering performance remain user checks. The source/build tests are not evidence those manual checks passed.

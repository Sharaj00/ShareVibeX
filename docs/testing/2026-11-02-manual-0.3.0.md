# ShareVibeX 0.3.0 — recording foundation user checks

This is the first recording tranche. It adds Video settings and FFmpeg command/capability tooling; it does not record the screen yet. The agent did not launch the application, capture/audio devices, native smoke harness, live clipboard or real FFmpeg. Internal process tests used hidden console-only children.

## Start

1. Exit the older instance through the tray. Extract the entire new ZIP to its own writable folder and start ShareVibeX.App.exe.
2. Open Settings > Video. Check the custom title bar, theme, card layout, scrolling and text legibility. The page must identify its recording-foundation scope.
3. If testing existing configuration, copy only your own data/settings.json to the new build's data folder before launch. Confirm shortcut/theme/image settings remain intact.

## Tool configuration

1. Leave FFmpeg path empty and click Test FFmpeg. If installed on PATH, it should show the resolved path/version and relevant listed capabilities. Otherwise it should explain how to select it. Screenshots must still work when FFmpeg is missing.
2. Browse to your FFmpeg executable, test it, save settings, reopen and verify the path. Test a relative override if using a portable tools folder.
3. Enter a missing path: the test must report that override rather than silently selecting another executable.
4. Change the path during a test or close Settings. Old results must not appear under the new path or in a newly opened window. No console windows should appear.
5. This test queries capabilities only. It must not start recording, create an output video, install tools or request microphone access.

## Options and preview

1. Set frame rate to 60, change encoder/preset/rate control, enable/disable cursor and choose MP4/Matroska. Check the command preview. Encoder changes should reset incompatible preset/tune choices.
2. Select Percentage 50: the example output should be 960×540. Select DivideBy 1.5: 1280×720. Select TargetSize with width 0 and height 720, aspect locked: 1280×720.
3. Choose target 1279×719 with aspect unlocked: output should pad to 1280×720, while the scale content size remains 1279×719. Input video_size stays 1920×1080 in all these example previews.
4. Switch the preview between Silent and With audio. Silent must have `-an` and no audio encoder; With audio should show the selected source and audio options. System/microphone choices show the future pipe, not a working capture session.
5. Try AAC/MP4 and Opus/Matroska; Opus/MP4 should show a compatibility error. DirectShow names are saved, but no device is opened by this page.
6. Add `-g 60 -metadata "title=My clip"`: preview should preserve the quoted value. Try `-vf scale=1:1` in Additional arguments: it should reject the duplicate filter route.
7. Enable custom mode with the default template: both audio previews should validate. Generated encoder/quality/preset/additional fields must be disabled. Remove `$output$`, add an extra filename, or use an unknown placeholder: show an error and refuse to save the invalid draft.
8. In custom mode with a positive time limit, add `-t $duration$` before the final `$output$`. Scaling modes other than Original need `$scale_filter$` in the output `-vf` value.
9. Save, reopen and verify Video values alongside General/Image. Reset recording options should restore only Video draft values; closing without Save should discard that reset and other edits.

## Screenshot regression

Capture, annotate, Copy and Save as before. Screenshot remains the default mode. Tray and hotkey must keep working after capture. Check full-color clipboard history/paste from a newly copied capture as in the 0.2.3 checklist. Real native behavior remains the user's verification.

# ShareVibeX 0.2.1 — user verification

Manual checks belong to the user. The agent did not launch this build, automate the desktop, run the native harness, change Windows settings, or touch the live clipboard. Internal/headless tests use synthetic windows and a deferred clipboard implementation.

Release evidence: 68 internal tests passed (37 core, 31 app), Release build zero warnings/errors. Independent source review identified a pending-settings-save close/reopen race; its regression failed first and passed after preventing user close during saving. Successful save and OS/application shutdown still close normally.

## Reported crash and fix

Read-only inspection of Windows .NET Runtime events identified an unhandled `Cannot re-show a closed window` exception in WindowVisibilitySnapshot.Restore after capture. The snapshot now tracks windows closed while hidden, skips closed windows/owners, and detaches lifecycle handlers after restoration. Cleanup exceptions are reported rather than escaping the async capture entry and terminating the tray process. Tests reproduce closure of a hidden window and its owner/child before restoration.

## Clipboard change and evidence limit

Image publication now awaits Windows clipboard flushing before completing the capture, retaining the image through publication/flush failure. This explicitly materializes the delayed image data before the capture window disappears. Internal tests verify publish/flush order, persistence in a deferred test clipboard after the image owner is disposed, and retaining the bitmap when flushing fails. Actual paste into other software and paste after tray Exit still require the user's tests below; they are not claimed from the internal checks.

## Suggested manual sequence

1. Exit any older ShareVibeX through its tray menu. Start the executable from the extracted 0.2.1 package. Confirm only a tray icon appears and Settings opens from its menu.
2. Capture an area and save it. Confirm the overlay closes, the file opens normally, the tray icon remains, and another capture works. Repeat with Settings open before starting capture, and after saving/closing Settings.
3. Capture and Copy. Paste into an image-capable app or a local chat draft without sending it. Confirm image dimensions and annotations. Repeat after closing Settings; optionally check that the copied image still pastes after tray Exit.
4. Under Image, try PNG, JPEG and WebP. Check the suggested extension and that an image viewer opens the result. Compare JPEG/WebP at quality 25 and 95. Confirm PNG's quality control is disabled. Cancelling Save should leave the same selection/editor active.
5. Under General, select System and check that mode/accent match Windows. If you independently change Windows appearance, confirm ShareVibeX updates. Select Contrast (AMOLED) and check black surfaces/readable focus. Save, restart and check persistence; closing without saving should restore the previous choice.

If anything fails, report the selected action, whether Settings was open, whether the tray icon disappears, and which build path you launched. The ZIP includes the tested source; old executables under earlier dist or test/bin directories remain older builds.
